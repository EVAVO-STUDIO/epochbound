# Campaign Data Contract

Epochbound content is stored as versioned JSON so campaigns can be reviewed in Git, validated without opening scenes, generated by tools and installed independently of engine code.

## Directory layout

```text
campaigns/
  campaign_id/
    campaign.json
    maps/
      first_map.json
      second_map.json
```

Packaged campaigns use `res://campaigns`. Installed player campaigns use the equivalent structure under `user://campaigns`.

## Identifier rules

Identifiers are lowercase and may contain:

- `a-z`
- `0-9`
- `_`
- `-`

Identifiers are references. Titles and display names are presentation. A map may be renamed for players without changing its identifier.

## Campaign manifest

A `campaign.json` file currently contains:

```json
{
  "schema_version": 1,
  "id": "example_campaign",
  "title": "EXAMPLE CAMPAIGN",
  "subtitle": "A NEW JOURNEY",
  "author": "Campaign Author",
  "description": "An original Epochbound campaign.",
  "start_map": "first_crossing",
  "start_era": "verdant",
  "map_files": [
    "maps/first_crossing.json",
    "maps/second_region.json"
  ],
  "intro": ["First page.", "Second page."],
  "actors": {
    "player": {"name": "HERO", "max_health": 32},
    "companion": {"name": "COMPANION", "max_health": 24}
  },
  "ruleset": {
    "combat_model": "action",
    "companion_enabled": true,
    "era_shifting_enabled": true
  }
}
```

`map_files` only accepts safe relative JSON paths. Absolute paths, parent-directory traversal and protocol paths are rejected.

## Map record

A world-builder map contains:

- `schema_version`
- `id`
- `display_name`
- `canvas`
- `bounds`
- `spawns`
- `eras`
- `terrain_palette`
- `terrain_cells`
- `collision_cells`
- `navigation_cells`
- `recovery_anchors`
- `entry_points`
- `layers`
- `interactions`
- `connections`

The newer world-builder fields are backward-compatible optional additions to schema version 1. Campaign Studio supplies defaults when opening an older schema-1 map, and only persists them after the author saves.

## Canvas, grid and bounds

```json
{
  "canvas": {
    "width": 800,
    "height": 480,
    "grid_size": 16
  },
  "bounds": {
    "left": 32,
    "right": 768,
    "top": 96,
    "bottom": 448
  }
}
```

`canvas` defines world dimensions and grid size. `bounds` defines the legal actor movement rectangle. The runtime camera follows the player across maps larger than the 640 by 360 presentation viewport.

Grid-backed records use integer cell coordinates. For a 16-pixel grid, cell `{"x": 10, "y": 12}` occupies world rectangle `160,192` through `176,208`.

## Spawns

Every map provides stable default `player` and `companion` spawn positions:

```json
{
  "spawns": {
    "player": {"x": 320, "y": 224},
    "companion": {"x": 280, "y": 232}
  }
}
```

These are used when starting directly in the map or when an incoming connection has no usable entry. Normal cross-map travel uses named `entry_points`.

## Eras

Each era contains:

- a stable identifier;
- a player-facing display name;
- a validated HTML hexadecimal palette;
- era-specific landmark records.

```json
{
  "id": "verdant",
  "display_name": "Verdant Age",
  "palette": {
    "sky": "819a91",
    "ground": "4f6550",
    "accent": "e5d89f",
    "structure": "53625b"
  },
  "landmarks": []
}
```

The primitive renderer supports `marker`, `sun`, `ruin`, `well`, `tree` and `dead_tree` landmark kinds. These are blockout contracts, not final art categories.

## Era availability

Terrain cells, collision cells, navigation cells, interactions, entry points, recovery anchors and connections may declare `available_eras`.

```json
{"available_eras": []}
```

An empty array means every era. A non-empty array restricts the record:

```json
{"available_eras": ["ashen"]}
```

A global cell and an era-specific cell may occupy the same coordinate. The era-specific cell wins in that era. Duplicate cells with the same coordinate and the same era scope are rejected.


## Interaction progression classification

Interactions are optional exploration surfaces by default. Capability gates on them remain visible in audit metrics but do not automatically become mandatory journey requirements.

Use a strict boolean only when an interaction is genuinely required for the authored progression route:

```json
{
  "id": "release_archive_lock",
  "progression_required": true,
  "required_capabilities": ["clockglass_sight"]
}
```

Map connections, story conditions and merchant conditions remain progression-critical without this flag. This distinction prevents optional lore from inflating softlock demand while preserving an explicit path for required interaction gates.

## Terrain palette

Terrain definitions separate visual identity from painted cells:

```json
{
  "id": "water",
  "display_name": "Water",
  "colors": {
    "default": "365a68",
    "verdant": "3f7180",
    "ashen": "493f49"
  },
  "blocked": true
}
```

Rules:

- IDs are unique and stable.
- `colors.default` is the fallback.
- Other colour keys must be declared era IDs.
- Every colour must be valid HTML hexadecimal colour text.
- `blocked` determines whether the terrain prevents actor movement.

Final production terrain definitions can later add tile-set, material, sound and animation references without changing the painted cell identity.

## Terrain cells

```json
{
  "x": 20,
  "y": 13,
  "tile": "path",
  "available_eras": []
}
```

Terrain is stored sparsely. Unpainted cells use the current era's base ground. Sparse storage keeps diffs readable and avoids serialising an entire empty grid.

## Collision cells

```json
{
  "x": 30,
  "y": 9,
  "available_eras": []
}
```

Collision cells are explicit solid cells layered over terrain. A cell blocks movement when either:

- it has an applicable collision record; or
- its resolved terrain definition has `blocked: true`.

Runtime movement samples the actor centre and corners, then resolves horizontal and vertical movement separately so actors slide along valid boundaries rather than becoming stuck on every diagonal contact.

## Navigation cells

```json
{
  "x": 21,
  "y": 13,
  "available_eras": []
}
```

Navigation cells form the companion's preferred four-direction route network. The runtime resolves a short breadth-first path through available, unblocked navigation cells. If the map has no applicable navigation cells, direct steering remains as a safe blockout fallback.

## Recovery anchors

```json
{
  "id": "east_recovery",
  "position": {"x": 448, "y": 232},
  "available_eras": []
}
```

Recovery anchors are safe companion relocation points. The nearest applicable unblocked anchor is used when the companion is too far from the player or when an era change leaves an actor in blocked space.

## Entry points

```json
{
  "id": "from_clockwood",
  "player": {"x": 480, "y": 216},
  "companion": {"x": 448, "y": 232},
  "available_eras": []
}
```

An entry point defines separate arrival positions for the player and companion. Every incoming connection names an entry point on its target map. Entry positions should be clear of collision and far enough from the return connection to avoid immediate retriggering.

## Layers

Supported layer types are:

- `terrain`
- `objects`
- `collision`
- `navigation`
- `effects`

Each layer has a unique identifier, z-index, visibility state and lock state. The current visual editor directly authors terrain, collision and navigation records while preserving the broader layer contract for later object and effects tooling.

## Interactions

```json
{
  "id": "old_well",
  "kind": "well",
  "position": {"x": 124, "y": 207},
  "radius": 58,
  "available_eras": [],
  "dialogue": {
    "verdant": "Dialogue in one era.",
    "ashen": "Dialogue in another era.",
    "default": "Fallback dialogue."
  }
}
```

Dialogue may be a single string or an era-keyed object. Non-default dialogue keys must resolve to declared eras.

## Connections

```json
{
  "id": "east_to_clockwood",
  "position": {"x": 512, "y": 216},
  "radius": 34,
  "target_map": "clockwood_edge",
  "target_entry": "from_bellweather",
  "target_era": "same",
  "trigger": "interact",
  "available_eras": []
}
```

Connection rules:

- `target_map` must resolve inside the same campaign.
- `target_entry` must resolve on that map.
- `target_era` is `same`, empty, or a declared era on the target map.
- `trigger` is `interact` or `touch`.
- `radius` must be positive.
- IDs are unique within the source map.

`same` preserves the current era when the target map supports it, otherwise the target map's first era is used. An explicit target era deliberately changes the era during travel.

## Validation guarantees

The validator rejects:

- unsupported schema versions;
- unsafe map paths;
- invalid or duplicate stable IDs;
- invalid palette and terrain colours;
- cells outside the grid;
- unknown terrain IDs;
- duplicate cells in the same era scope;
- invalid era references;
- invalid spawns and marker positions;
- missing target maps, entries or eras;
- invalid connection triggers;
- unsupported layer and landmark types.

Warnings identify incomplete but playable blockout conditions, such as maps with no terrain palette, navigation cells, recovery anchors or entry points.

## Schema evolution

Every campaign and map declares `schema_version`. New engine versions should add explicit migrations rather than silently interpreting old data differently.

Migration rules:

1. Never destroy the original file before a migrated copy validates.
2. Migrations move forward one version at a time.
3. Runtime loading rejects unsupported versions with a useful error.
4. Editor saves use the current schema only.
5. Stable identifiers and world-state keys survive migrations.
6. Additive optional fields may remain in the current schema when old records have unambiguous defaults.

## Save-game separation

Campaign definitions describe authored content. Save games describe a player's state inside that content. Save records must reference campaign ID, campaign content version, map ID, era ID and stable world-state keys; they must not copy entire campaign definitions.

This separation allows campaigns to be updated while still giving the loader enough information to reject or migrate incompatible saves deliberately.
